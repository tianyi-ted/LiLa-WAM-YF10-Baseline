# 动作 Chunk 尾部复用与闭环重规划：性能优先实验路线

更新时间：2026-10-22。状态：研究设计，尚未实现本文的新算法或启动新训练。

本文以此前讨论的“动作尾部加噪复用 → 验证连续性与少步生成 → 训练匹配 → 可选逐位置时间与流式生成”为主线。成功率、推理速度、运行效率、动作平滑连续性都可以成为核心验证点，而不是只追求成功率。观测驱动的回退是保护纠错能力的可选机制，不是唯一研究目标。另一份AI建议仅作为并行思路比较；原参考文件已由用户移除，本文不依赖它。

本文件不替换原空间意图路线，也不修改任何已有模型或 YAML。

阅读顺序：先看第1节通俗解释，再按第14节执行实验；第2～8节是实现细节，第9～13节是指标、边界和参考。第14节为统一推进清单，避免把全部可选分支都当作必做实验。

## 1. 核心判断与目标

工程目标是让模型在新观测到来后利用上一段未执行的动作，减少每次从零生成的随机变化，同时保留纠错能力：

> 能否利用尚未执行的旧动作，减少新动作生成的计算、等待与跳变，同时仍能根据最新观测调整计划？

近期不叠加 OPD、全局/空间意图模块、世界模型、MeanFlow 或 RL。先以现有 DINO-B+h512 Flow Matching 策略完成受控验证。即使方法与已有研究重合，只要有稳定性能收益，也可以作为有用改进与后续baseline。

不预设所有实验都必须提升成功率。先选清楚本轮主要目标，再记录其他指标的代价：

| 核心目标 | 通俗解释 | 应记录什么 |
|---|---|---|
| 成功率/鲁棒性 | 更容易完成任务，遇到变化还能纠错 | 成功计数、扰动恢复、失败类型 |
| 推理速度 | 生成一段动作需要更少计算或时间 | DiT调用次数NFE、平均/p95延迟、显存 |
| 运行效率 | 机器人少等待、更快完成任务 | 等待时间、完成步数、真实墙钟耗时 |
| 平滑度/连续性 | 相邻chunk之间少跳变、少犹豫 | 边界动作差分、动作变化率、反复开合等 |

例如，成功率基本不变、调用从10次降到5次、动作更连续，就是有意义的结果。若为了速度牺牲少量成功率，应报告完整取舍而不是隐藏退化。动作生成变快不一定使任务完成更快；动作更平滑也不一定更准确。

### 1.1 本轮确定的主线顺序

```text
P0：冻结可用checkpoint及评测协议
  ↓
P1：旧动作尾部加噪初始化，保持10次速度场调用
  ↓
P2：有潜力后测试5次调用，并排查训练—推理起点失配
  ↓
P3：匹配source训练，与同起点继续训练的控制组比较
  ↓
P4：有必要才加入观测驱动回退，改善失效旧计划的纠错
  ↓
P5（可选）：逐位置生成时间与噪声调度 → 流式/异步动作缓冲
```

不要求先复现复杂论文，也不要求先实现逐位置时间。噪声复用只作为可选诊断，不是主线必经步骤。先做相同调用次数的比较便于解释原因，再单独减步；若以速度或连续性为目标，同样可以推进，但要明确成功率和纠错代价。

### 1.2 先看懂：以RoboTwin的32步/16步为例

**这里描述的是拟议的新功能，不是说当前推理已经实现尾部回喂。**原模型预测32步，执行前16步；新路线要额外保留没有执行的后16步。

```text
第一次预测：[a0 … a15 | a16 … a31]
实际执行：  前16步      后16步缓存、不执行

执行后读取新图像和状态，要重新预测：
            [a16 … a31 | a32 … a47]
             有旧预测     没有旧预测
```

所以，旧chunk的后16步会移动到新chunk的前16步位置，不是原样放在新chunk后面。

新生成过程可以理解成：

```text
[旧后16步 + 噪声 | 新的16步纯噪声]  ← 起点Z
                   ↓
         结合最新图像、状态、任务条件
                   ↓
       DiT反复修改整段32步，得到新chunk
                   ↓
       执行新chunk前16步，缓存新后16步
```

旧动作是“草稿”，不是必须照着执行的答案。新32步都允许修改，尤其新前16步也不能锁死，否则抓偏了还可能按旧计划继续抬升。

### 1.3 起点Z是什么？

Z不是额外网络，只是每次生成开始时装进动作张量的数值。原来的Z是32步纯噪声；新方法的Z是“旧动作草稿加噪声，加上尚无草稿的新尾部”。

默认旧计划权重为1时：

```text
Z前16步 = 对齐的旧预测P + sigma × 新噪声
Z后16步 = 新噪声
```

sigma控制给草稿加多少噪声，操作在归一化动作空间进行。它不是“执行第几帧”，也不是生成进度。构造Z后仍从生成时间0积分到1，不会自动少调用DiT。

### 1.4 为什么训练batch还要准备旧计划？

推理是连续执行的，上一轮预测直接存在缓存里。但训练样本通常会打乱：一个batch可以同时有不同任务、不同episode、不同帧，**上一个batch不是当前batch在时间上的前一段**。

假设当前训练样本对应同一episode的第100帧：

```text
第84帧图像/状态 → 固定baseline预测第84～115步
                                      ↓
                   取后16步预测：第100～115步，作为P

第100帧图像/状态 + P + 新噪声 → 训练生成第100～131步
                                        ↑
                              专家动作作为训练答案A
```

这模拟了“16步前曾规划过一次”。P来自模型在更早观测下的预测，不能直接拿第100～115步专家答案代替它。为省训练计算，可以提前生成P并按episode和帧号缓存；训练仍可正常shuffle。

起点变了，学习的修正方向也要变：

```text
原始训练：从epsilon出发，学 A-epsilon
新训练：  从Z出发，学 A-Z
```

一句话：原来是“从随机草稿写出动作”，现在是“结合新观测，修正旧草稿并补出新尾部”。离线旧计划与部署时自己的预测仍可能不同，因此这叫匹配起点构造，不保证所有闭环分布差异都被消除。

### 1.5 噪声调度、逐位置时间和流式生成的区别

| 层级 | 直观含义 | 本路线安排 |
|---|---|---|
| 尾部加噪复用 | 前16步有旧草稿，后16步没有 | 第一版主线 |
| 噪声强度调度 | 不同位置或不同重规划轮次，给不同量的噪声 | 固定sigma先验证，自适应规则后置 |
| 逐位置生成时间 | 有些动作快生成好了，有些还接近纯噪声 | 可选升级，必须配套训练和时间输入 |
| 流式生成 | 执行已完成的近端动作，缓冲区移动，末尾补噪声，其他位置继续生成 | 可选后续阶段 |

“前半旧动作加噪、后半纯噪声”只是在构造不同位置的起点，整段仍可共用一个生成时间。真正逐位置时间则需要告诉模型每个位置各自的生成进度。流式生成不只是缓存后半段：它还要管理移动缓冲区和连续的生成进度；是否与环境执行并行，是额外的同步/异步设计问题。

## 2. 统一的数学约定与适用边界

### 2.1 时间约定必须统一

本项目训练为：

```text
epsilon ~ N(0,I)
X_s = (1-s) * epsilon + s * A_gt
target_velocity = A_gt - epsilon
s=0：噪声端；s=1：动作端
```

因此，对旧计划 P 做中间时间初始化时应写：

```text
X_s0 = (1-s0) * epsilon + s0 * P
```

若把噪声比例定义为 alpha，则 `s0=1-alpha`，不是 `s0=alpha`。下面主线采用source重构、从s=0积分到1；不把sigma误当成生成时间。

### 2.2 加噪不等于理论保证

只有在端点分布、条件、噪声耦合及模型速度场等假设成立时，从正确的条件中间分布开始才有相应输运结论。旧观测下预测的动作尾部，不保证服从新观测下的动作分布。即使无条件边际接近，也不能推出条件生成正确。

加噪可能弱化旧计划误差，但不会自动把任意错误动作拉回正确训练分布。接触失败、物体移动、夹爪状态变化时尤其需要重新规划。本文把 warm start 视为待验证的近似，而不是理论兜底。

### 2.3 当前噪声并非预先设计的时间相关噪声

代码使用 `torch.randn_like` 或 `torch.randn`，基础噪声各元素独立。动作序列的统计联系由网络学习；“整段联合生成”不保证最终动作平滑或物理可行。

### 2.4 逐位置时间需要训练与结构支持

当前 DiT 使用样本级标量生成时间，不能只把输入改成不同噪声强度，就称为正确的 Diffusion Forcing。正式逐位置版本需要时间张量、动作 token 级时间条件、训练路径、损失与采样调度一起设计。

### 2.5 不能直接移植 HybridFlow 的结论

HybridFlow 使用 MeanFlow 平均速度提案和局部精修；当前模型是普通瞬时速度场。对普通 FM 额外加噪再积分可以作为启发式，但其效果和2-NFE能力不能从 HybridFlow 直接推得。

## 4. 时间对齐：先保证实现正确

用环境步 t 与生成时间 s 区分两条时间轴。预测长度H，实际执行步数E。

```text
旧计划：[a_t ... a_(t+E-1) | a_(t+E) ... a_(t+H-1)]
                           执行后剩余尾部
新计划：[a_(t+E) ... a_(t+H-1) | 新的E步]
```

新计划前 `H-E` 个位置有可对齐旧预测，其余位置没有。务必按实际执行步数移动，不按生成调用次数、墙钟时间或“上一帧”模糊对齐。

实现要求：

- 缓存归一化、未裁剪的完整预测，另行保存实际发送动作以诊断裁剪影响；
- episode reset、任务切换、异常终止时清空所有缓存；
- 第一次生成无历史时走原始纯噪声路径；
- 夹爪与位移分量分别统计，不能因夹爪开合变化就判为有害抖动；
- 每次重规划刷新观测，不因缓存动作而复用过时视觉条件；
- 为FM采样设置独立随机数生成器，保证环境seed与策略噪声seed可分别复现；
- 检查所测试推理入口是否实际使用 `smooth_actions`，不能仅凭YAML字段存在就认定已平滑。

### 4.1 原模型结构：每次独立生成

```text
当前图像 I_t → 冻结DINO-B → 多层视觉特征 → 融合/视觉适配通路 ─┐
当前状态 q_t → 归一化 → 本体状态token                         │
VTT → 任务条件token                                         ├→ 动作DiT
独立高斯 X_0 → 动作投影 → H个动作token                       │   ↓
生成时间 s → time embedding → DiT时间调制 ───────────────────┘   速度场
                                                               ↓
                              Euler积分，更新整段动作，重复K次
                                                               ↓
                              归一化动作 A_hat:[B,H,d_a]
                                                               ↓
                            反归一化，执行前E步，丢弃剩余部分
```

当前未来特征预测辅助头继续按baseline训练设置保留；它不是本路线的旧动作来源。旧动作来源是上次真实推理得到的完整动作chunk，而不是未来帧或专家标签。

### 4.2 新结构第一版：只改变起点，不改变DiT网络

```text
上一轮完整归一化chunk缓存 [B,H,d_a]
               ↓ 按已执行E步移位
旧尾部 P [B,H-E,d_a] + 新噪声 epsilon
               ↓ SourceBuilder
Z前H-E步 = lambda*P + sigma*epsilon
Z后E步   = epsilon
               ↓ 作为X_0，不是额外token
        原有动作投影 → 原有DiT → 速度场 → 原有积分器
                              ↑
                   最新图像、最新状态、相同任务条件
                              ↓
               新完整chunk → 缓存，并执行前E步
```

与S2/G2的区别：没有新增意图token；与S-residual的区别：没有修改视觉特征。它直接修改“动作生成从什么数值起步”，视觉/状态/VTT条件路径保持原样。

这一版增加的是缓存与数值操作，不增加可训练参数。模型仍要用完整K次速度场调用，不能因为输入接近动作就自动减少调用次数；加速是后续独立实验。

### 4.3 缓存对象与运行顺序

建议在Meta-World `Policy`中新增以下状态，以下字段均为计划中的接口：

| 字段 | 形状/类型 | 用途 |
|---|---|---|
| `previous_chunk_norm` | `[1,H,d_a]`或None | 上一完整归一化预测；必须detach |
| `executed_since_plan` | int | 实际已发送给环境的动作数 |
| `previous_noise` | `[1,H,d_a]`或None | 仅噪声复用诊断需要 |
| `previous_features` | 按编码器定义 | 仅选择性回退需要 |
| `queue` | E个实际动作 | 执行队列，与完整预测缓存分离 |
| `policy_generator` | torch.Generator | 动作采样RNG，与环境RNG分开 |

建议将一次重规划拆为：

```python
# 设计伪代码，不是当前已存在接口
def replan(observation):
    condition = encode_latest_observation(observation)
    eps = sample_noise(generator=policy_generator)
    P, M = align_previous_chunk(previous_chunk_norm, executed_since_plan)
    Z = build_source(eps, P, M, mode, prior_strength, prior_noise_std)
    new_norm = integrate_velocity(Z, condition, s_start=0, s_end=1, nfe=K)
    previous_chunk_norm = new_norm.detach().clone()
    executed_since_plan = 0
    real_actions = denormalize(new_norm)
    queue = list(real_actions[:E])

def step(observation):
    if not queue:
        replan(observation)
    action = clip(queue.pop(0))
    executed_since_plan += 1
    return action
```

标准队列语义下重规划时计数就是E。若未来有执行中断、跳步、动作合并，必须按实际发送/执行语义重新定义计数，不可仍硬编码E。

Meta-World现有episode reset处只调用 `policy.queue.clear()`，未来实现需改为统一 `policy.reset_episode()`，同时清理全部新缓存；`set_task()`也应调用同一重置逻辑。此处尚未修改代码。

### 4.4 SourceBuilder的明确参数

```text
mode=cold：Z=epsilon，完全原始路径
mode=tail_prior：在有效旧尾部上使用lambda*P+sigma*epsilon
prior_strength=lambda：旧计划均值权重，首轮固定1.0
prior_noise_std=sigma：归一化动作空间的噪声标准差
```

mask M:[B,H,1]只表示“该位置有无可对齐旧预测”，不表示忽略动作监督，也不改变之前padding mask的约定。无有效预测时Z直接取标准高斯，不乘sigma。

先试sigma=1.0，再试0.5；这只是有限筛选，不保证最优。lambda=0且sigma=1时，全部位置应恢复cold；该等价性可作为单元测试。sigma=0不推荐作为第一版，因为更容易重复错误旧计划。

### 4.5 第二版：训练匹配后改变什么？

仍然使用相同DiT参数形状，不新增第二个模型或视觉主干。改变的是训练batch中起点Z的来源和目标速度：

```text
DataLoader：当前专家动作A、当前图像/状态、任务条件
                     +
离线先验缓存：更早观测预测的旧chunk尾部P、有效mask M
                     ↓
归一化到相同动作坐标系 → SourceBuilder → Z
                     ↓
X_s = (1-s)*Z + s*A
                     ↓
DiT(X_s,s,当前条件) → v_pred
                     ↓
L_action = mean((v_pred - (A-Z))^2)
                     +
原baseline已有的未来视觉特征辅助loss（保持权重不变）
```

基线数据集的动作尾部padding、未来帧截断策略保持不变。先验缓存若覆盖到旧episode外的位置，其M应为0；这与当前专家目标中的既有终止保持监督是两个不同问题。

训练先验建议按 `(episode_id, current_anchor, source_anchor, E, H)`保存。通常 `source_anchor=current_anchor-E`；episode开头找不到合法source时使用cold，不从上一episode借用。缓存时记录checkpoint、图像处理、动作统计文件的标识，防止先验坐标系不一致。

一个可执行的初始训练配方是：每个样本以0.5概率使用cold，否则使用tail_prior；这只是初始建议，最终需要cold-only和prior-only对照。当前数据shuffle和epoch覆盖方式不必改变，不涉及WeightedRandomSampler。

### 4.6 第三版：观测驱动回退放在哪里？

```text
最新观测特征、上一观测特征/执行诊断
                  ↓
             失配评分器
                  ↓
          选择cold或tail_prior
                  ↓
             SourceBuilder
                  ↓
              原始DiT积分
```

评分器放在每次重规划开始时，不放在每个DiT block，不给视觉特征做残差注入。初版只使用规则，避免重演“gate大小变化但性能原因不清”的问题。

可以先使用校准后的视觉变化阈值作为启发式，并记录触发是否合理；它不是可靠的计划失效真值。若无法区分正常动作引起的视觉变化与异常，不应强行启用。

cold回退必须真正构造Z=epsilon。固定周期cold和相同触发率随机cold是必要对照：只有自适应比这些简单策略更好，才说明评分器有价值。

### 4.7 备选结构：旧尾部作为条件，而不是起点

仅当source复用持续失败、但旧计划在诊断中确实包含有用信息时，才测试：

```text
P+有效mask+新horizon位置编码 → 小型MLP → 历史计划token
                                              ↓
当前视觉/状态/VTT token + 历史计划token + 高斯动作token → DiT
```

此时动作仍从标准高斯生成，历史计划通过条件通路提供参考；需要新增参数并训练。训练应加入计划丢弃、模型预测先验和适量扰动，避免只学复制专家。默认不同时启用source复用和历史token，以便判断是哪条路径有用。

这属于此前“作为辅助条件”的备选方案，不是当前必须实现的第四个网络分支。

## 5. 第一阶段：旧动作尾部加噪的推理验证

### 5.1 固定基线

先选择一个已通过训练/评测一致性检查的原始DINO-B+h512 checkpoint和一个horizon组合。按第14节的RoboTwin32/16方案可直接对接既有baseline；若选择Meta-World实施，则单独固定其checkpoint，优先C8/E4。先只选一个平台开展，不要求两平台同时实现。冻结数据、相机、归一化、VTT、checkpoint、动作裁剪和episode长度。

先选4～6个有代表性的任务：包含运动、抓取和接触，不只挑容易任务；在运行新方法前记录任务名单。RoboTwin建议名单见第14节；Meta-World候选包括push、pick-place、door-open、peg-insert-side、button-press，实际名称以配置为准。

### 5.2 最小筛选矩阵

| ID | 方案 | NFE | 解释 |
|---|---|---:|---|
| B10 | 独立高斯冷启动 | 10 | 当前参照 |
| W10 | 旧动作尾部加噪作为source | 10 | 低成本但分布失配的探索性测试 |
| B5 | 独立高斯冷启动 | 5 | W10完成后再检查减步本身损失 |
| W5 | 同W10 | 5 | 仅在W10无明显退化时运行 |
| N10（可选） | 对齐复用旧噪声 | 10 | 有疑问时区分旧噪声与旧动作的作用 |

N10不是论文复现或创新声明，只是诊断控制。可用：

```text
epsilon_new[k] = rho * epsilon_prev[E+k] + sqrt(1-rho^2) * eta[k]
```

用于重叠位置，新增尾部使用独立高斯。先固定 `rho=0.5`，有信号再测试 `rho=1`。这维持各位置高斯边际，但缓存来自历史闭环，不保证与当前条件独立，不能宣称完全保持原条件分布。

W10/W5先固定起点方案，不同时扫描多个机制：

```text
X_0[:H-E] = P + sigma * epsilon[:H-E]
X_0[H-E:] = epsilon[H-E:]
```

初筛 `sigma=0.5,1.0`，从s=0积分到1。必须标注为“未训练匹配source的启发式warm start”，不是已复现的WarmPrior。它不一定比冷启动好，失败不能否定训练匹配后的方法。

不要在第一阶段把混合噪声尾部与单一 `s0>0` 强行组合；新末尾没有旧计划，统一标量时间不能同时表达“前缀部分生成、尾部纯噪声”的训练语义。

### 5.3 进入下一阶段的条件

先每任务20个episode进行筛选，候选再做每任务50个episode及多个评测seed。若仅更平滑但成功率下降或恢复更慢，先量化这种取舍，再按本轮目标决定是否推进；不能只凭平滑指标就宣布全面改善。

推理实验无稳定正收益时，不必穷举sigma与rho；可允许一次训练匹配source的独立验证，以区分算法无效与分布失配。之后仍失败就停止该分支。

### 5.4 第二阶段：独立验证减步收益

只有W10测试完成后才运行B5/W5，先保持同一checkpoint与相同source参数。比较B10对W10回答“是否提升生成质量”；比较B5对W5回答“低预算是否更有效”。若W5只恢复到B10水平，其价值是效率，不应写成绝对成功率提升。

10次减少到5次只减少动作速度场调用，DINO编码等固定开销仍然存在，不代表端到端延迟一定减半。若W10失败，不强行用W5掩盖训练失配。

## 6. 第三阶段：训练与推理匹配的动作先验

这是性能改进的训练阶段，不以创新性为前提。可以参考WarmPrior，但先实现适配本项目的最小source训练，不把完整复现其他框架作为先决条件。

对齐后的旧计划为P，前缀有效mask为M，候选source：

```text
Z = M * (lambda * P + sigma * epsilon) + (1-M) * epsilon
X_s = (1-s) * Z + s * A_gt
target_velocity = A_gt - Z
```

这里是改变source分布，不能继续使用 `A_gt-epsilon` 作为监督目标。lambda为实验系数，不等同于生成时间。先固定lambda=1，不同时引入逐位置时间。

### 6.1 训练先验从哪里来？

不能把 `P=A_gt` 的重叠区直接当作真实部署先验；这会泄漏目标并让模型通过复制取得虚假的低loss。

推荐顺序：

1. 固定baseline，以同episode更早时刻的图像/状态生成旧chunk；按实际E步移动尾部；
2. 将尾部缓存到磁盘，记录生成checkpoint、条件时间、目标时间和mask，不跨episode取样；
3. 当前时刻专家chunk只作为目标，不提供给旧计划生成器；
4. 缓存避免每个训练batch额外在线运行一个完整teacher；记录预计算NFE、GPU小时、磁盘量；
5. 训练时加入无先验样本和适量先验扰动，确保首次启动、失配及放弃旧计划的路径可用；
6. 注意固定baseline先验与新策略自生成先验仍有分布差异。若有必要，后续单独刷新一次缓存，不能声称已消除所有闭环偏差。

专家相邻轨迹可以用于读取和对齐单元测试，但不能替代模型预测先验的正式测试。

### 6.2 公平训练对照

- 快速筛选：baseline继续训练4轮控制组，与匹配source微调4轮使用相同初始checkpoint、LR、batch、seed及训练样本预算；
- 最终结论：冷启动与source方法各从头训练，保持相同epoch规划与scheduler，预先固定比较epoch；
- 不能把baseline epoch40直接与“epoch40再微调4轮”归因比较；
- 先在同NFE下比较成功率，再测试少NFE，不把换训练方式与减步混在一个结果中。

## 7. 第四阶段：观测驱动的选择性复用与回退

前提：固定复用已有可复现收益，或明确表现出“无扰动平滑、扰动下粘滞”的可解释失败。

### 7.1 低成本版本：先验证失配信号

候选信号必须在部署时可获得：

- 当前/前次状态变化与动作裁剪率：低成本，但无法独立判断目标物体是否移动；
- 当前/前次视觉特征变化：复用已有DINO编码，不增加第二个视觉主干；但机器人正常运动、相机移动也会产生变化，不能把它直接叫预测误差；
- 旧计划与一次当前条件速度场探测的分歧：增加1次NFE，可以诊断，但需要与等算力冷启动对照；
- 学习短跨度状态/局部视觉预测后得到“预测与实测”误差：更接近真正失配，但需要新模块与监督，后置。

先做诊断相关性：信号是否区分“正常推进”与“旧计划失效”？若不能区分，不应直接接一个复杂gate。

### 7.2 由失配决定计划可信度

失配分数d标准化后，构造可信度r；初期使用可解释阈值，不急于训练MLP：

```text
r = sigmoid((threshold-d)/temperature)
P_strength = r
sigma = sigma_min + (1-r) * (sigma_max-sigma_min)
```

必须明确：提高sigma并不等于冷启动，因为source均值仍为P。真正的完全回退应显式选择 `Z=epsilon`；不要只增加噪声就宣称丢弃旧计划。

先做chunk级“保留/冷启动”二选一，再尝试按位置降低可信度。没有异步延迟时，不把未执行的近端动作全部硬锁定；接触纠错可能正需要修改新chunk第一步。

任何自适应source都需要匹配训练或明确标注为推理启发式。先用固定source训练模型做诊断，再决定是否训练包含可信度变化的模型。

### 7.3 必须回答的研究问题

1. 相比固定warm start，是否在保留连续性的同时更快放弃错误计划？
2. 是否优于简单随机重启或固定周期冷启动，而非仅多用了算力？
3. 是否只依赖某个平台的状态幅值或相机背景？
4. 能否在相同NFE/延迟预算下提高扰动恢复或成功率？

首先判断这些机制是否改善本轮选定的核心指标，并报告其他指标的代价，暂不以创新性筛选方案。文献排重与论文贡献包装留待收益明确之后。

## 8. 可选后续升级：逐位置时间、噪声调度与流式执行

先完成简单尾部复用与训练匹配，再根据核心目标选择是否进入。本阶段不是必须等待成功率提升：若研究重点是连续动作输出或低延迟，也可在基本质量可控后推进。观测驱动回退可独立测试，不是进入流式生成的硬性前提。

逐位置时间需要：`s:[B,H]`、动作位置级时间embedding及调制、匹配的训练插值和速度目标，以及明确的多位置积分路径。若采用各位置s_k随调度变量u变化，还需考虑 `dX_k/du=(ds_k/du)*v_k`，不能省略不同位置积分步长。

不要默认需要把所有attention改成因果形式；是否因果取决于定义的生成条件与mask设计，需要与原模型单独比较。不能把任何位置加噪都命名为Diffusion Forcing。

异步实验再引入真实推理延迟、committed prefix和RTC对照，分别报告模拟延迟与真实墙钟延迟，不与同步仿真混淆。

## 9. 指标、扰动与预算

### 必须记录

- 每任务成功率、宏平均、原始成功计数、配对episode结果；
- 环境/初始状态seed与策略噪声seed，二者独立；
- 训练seed：同checkpoint推理消融不需要重训，最终结构/训练比较尽量至少3个训练seed；
- NFE、重规划频率、平均/p95生成延迟、视觉编码耗时与动作生成耗时；
- 边界动作差分与chunk内部差分分别统计，按动作维度范围归一化；
- 对齐重叠区计划差异、动作裁剪率、冷启动比例；
- 扰动恢复时间、失败类型、完成步数；
- 额外训练/缓存成本与显存峰值，不能只报部署FLOPs。

分组报告任务与评测seed，必要时使用配对bootstrap等方法计算差异区间；不把所有任务样本当成完全同质独立样本。不能凭单seed约1个百分点差异得出稳定优势。

### 扰动设置

先做无扰动，再在独立协议中测试目标物体小位移、短时动作丢失或可控观测延迟。保持任务目标语义与success函数有效。只在可安全修改的仿真中加入扰动，不在真机直接测试强扰动。随机背景不等同于执行中物体突变，应分开报告。

### 预算约束

先4～6任务筛选，再MT50正式测试；有信号后再移植RoboTwin。无需每个候选都做50任务×多seed完整训练。独立新目录存结果，不能覆盖历史baseline。

## 10. 停止与转向条件

| 观察结果 | 决策 |
|---|---|
| 固定复用和冷启动相近，动作也无明显跳变 | 不继续堆时间平滑机制，优先查当前视觉/控制瓶颈 |
| 平滑改善但接触成功率下降 | 研究计划失配与回退，不加强一致性约束 |
| 匹配source训练后仍无收益 | 停止单纯warm start分支，记录负结果 |
| 自适应与随机/周期回退无差异 | 失配信号或方法无效，不扩大gate网络 |
| 少NFE时有收益、10NFE时无收益 | 可转向效率研究，但必须报告完整成功率—延迟曲线 |
| 固定复用成功、自适应也有稳定增益 | 进入多任务、多seed、跨平台与正式相关工作对比 |

RoboTwin最新v2 gate0 epoch40：Residual-on为clean73.0%、randomized61.2%、总体67.1%；真正Residual-off为73.6%、60.4%、总体67.0%。这只说明当前checkpoint上注入未呈现稳定净收益，不证明“空间信息无效”或“仅训练有效”。

## 12. 与并行参考思路的异同及参考资料

### 12.1 相同与不同

| 内容 | 并行参考思路 | 本文主线 |
|---|---|---|
| 基础动机 | 复用旧动作减少重启变化 | 相同，验证成功率、效率、连续性中的具体收益 |
| 初始化 | 较强调中间生成时间加噪与跳步 | 先用旧尾部构造source，从0积分到1 |
| 新尾部处理 | 强调逐位置噪声调度 | 新增位置保持标准高斯，不先改时间通路 |
| 结构升级 | 较早引入逐位置时间/流式生成 | 先匹配训练，必要时再做观测驱动回退 |
| 理论预期 | 较乐观地把加噪当分布修复 | 明确是待实测近似，不承诺提升 |
| 近期目标 | 连续性、少步生成及研究方向 | 成功率、速度、运行效率、连续性均可作为核心指标，分开验证 |

这里只保留概念比较，不依赖已移除的参考文件。后续实现以第14节推进清单和第4节结构为准。

### 12.2 可借鉴的工作

以下为本次查阅的官方项目或论文入口；部分仅核对摘要/项目说明，不能代替全文与代码复现。

1. [WarmPrior：官方代码](https://github.com/sinnnj/warmprior-bc)：用此前预测尾部构造下一次source；与“旧动作加噪初始化”高度重合，是最直接对照。需进一步核对其训练先验构造。
2. [RTC：Real-Time Execution of Action Chunking Flow Policies](https://arxiv.org/abs/2506.07339)：面向异步执行的前缀约束与补全。同步warm start实验不能声称复现RTC。
3. [EAPN](https://arxiv.org/abs/2610.06090)：传播执行对齐的噪声历史并引入动作上下文。只做噪声复用/移位不是足够的新贡献。
4. [Diffusion Forcing](https://arxiv.org/abs/2407.01392)、[官方实现](https://github.com/buoyancy99/diffusion-forcing)：逐token噪声与序列生成的基础工作，结构与训练需要匹配。
5. [πR²官方项目](https://pi-r2-flow.github.io/)：包含逐位置生成时间、新鲜本体状态和延迟自适应调度，与逐位置重规划高度相关，需进一步阅读全文排重。
6. [HybridFlow](https://arxiv.org/abs/2602.13718)：MeanFlow提案、ReNoise、局部精修，非当前普通FM的直接推理插件。
7. [Action-to-Action Flow Matching](https://arxiv.org/abs/2602.07322)：历史动作/本体信息驱动生成起点，也是source设计的重要近邻，后续实施前进一步精读。

以上资料用于避免实现错误、借鉴有效方法，不作为近期启动实验的门槛。全面创新性分析放到出现可靠性能收益之后。

实施验收：关闭开关且使用相同RNG状态时，生成结果应与原始路径一致；sigma和strength只对有先验的位置生效；不同episode无缓存串扰；训练速度目标明确是A-Z；匹配训练的checkpoint在推理时必须配合相同source规则。缺少缓存文件或统计标识不一致时应报错，不静默使用专家目标代替旧计划。

## 14. 详细实验推进计划：按此顺序执行

**状态说明：以下均为待执行计划，不是已完成实验。当前只完成文档，尚未实现动作复用、缓存生成器或新增训练开关。**

### 14.1 全程总览

| 阶段 | 核心问题 | 是否训练 | 必要产出 |
|---|---|---|---|
| P0 基线与实现检查 | 缓存、时间轴、默认行为是否正确？ | 否 | 固定协议、单元测试、运行检查 |
| P1 同算力复用 | 旧尾部是否改善生成质量或连续性？ | 否 | B10/W10两种sigma的筛选结果 |
| P2 减步 | 少调用时是否仍保持可用动作？ | 否 | B5/W5及延迟—质量曲线 |
| P3 训练匹配 | 学会修正旧计划后是否更好？ | 是，先4轮 | 冷启动控制组、先验训练组 |
| P4 选择性升级 | 根据失败原因，只选一个机制改进 | 视分支而定 | 回退/位置调度/计划token对照 |
| P5 逐位置与流式 | 能否连续输出动作并降低等待？ | 通常需要 | 逐位置训练、滑动缓冲、延迟实验 |
| 正式验证 | 收益是否稳定且能泛化？ | 候选模型多seed | 全任务、配对结果、成本与置信区间 |

先明确每轮的主指标：成功率、推理速度、运行效率、连续性四者任选其一或多个；其余作为伴随指标。速度/连续性为主时，事先约定可接受的质量退化范围，不能看到结果后临时放宽。

### 14.2 P0：固定协议与正确性验收

以RoboTwin32/16为默认示例：

- 使用原始DINO-B+h512 baseline epoch40，不启用G2、S2、S-residual；
- 预测32步、执行16步，先保持10次DiT调用；
- 固定统计文件、相机、图像处理、VTT、裁剪、平滑和任务步数上限；
- 不把baseline epoch40与C32混成同一参照：C32是额外微调4轮版本；
- 保存checkpoint哈希、代码版本、完整配置及实际生效的评测配置路径。

实现第4节中的可选缓存、SourceBuilder、reset及独立策略RNG。无需修改DiT结构。

验收清单：

- [ ] 关闭复用时，相同随机状态下与原实现一致；
- [ ] lambda=0、sigma=1时起点与cold一致；
- [ ] 旧第16～31步正确对应新第0～15步；
- [ ] 首次生成、reset、任务切换都清空旧计划；
- [ ] 只复用合法的未执行预测，不混入别的episode；
- [ ] 归一化、dtype、设备、动作形状正确，无NaN/Inf；
- [ ] 单任务少量episode能正常结束，指标文件完整。

**通过条件：所有正确性测试通过。**此时不能因一两个episode成功就宣称性能提升。

### 14.3 P1：10次调用下的尾部复用筛选

固定lambda=1，只比较：

| 实验ID | 初始化 | NFE |
|---|---|---:|
| B10 | 全部标准高斯 | 10 |
| W10-S1 | 前16步旧尾部+sigma=1.0噪声，后16步标准高斯 | 10 |
| W10-S05 | 前16步旧尾部+sigma=0.5噪声，后16步标准高斯 | 10 |

建议先固定5个RoboTwin任务：`hanging_mug`、`open_microwave`、`scan_object`、`stack_blocks_two`、`stamp_seal`。如更换名单应在新方法运行前记录，不能按结果挑任务。

每任务20次，clean和randomized分开：`3设置×5任务×20次×2环境=600次episode`。这是快速筛选，统计规模不足以支持最终结论。

同时记录成功计数、完成步数、边界动作差分、内部动作变化、夹爪变化、裁剪率、延迟、失败类型。RoboTwin关节目标差分不是实际物理加速度，有真实关节轨迹时另行统计。

**决策：**

- 质量接近但更连续，或质量更好：进入P2；
- 更平滑但接触失败增多：记录权衡，优先检查旧计划粘滞；
- 无明显收益：不无限扫sigma，可允许P3一次匹配训练验证分布失配；
- 实现或坐标系有问题：返回P0，不用调sigma掩盖bug。

### 14.4 P2：验证5次调用，再决定是否试3次

从P1选一个sigma，不继续同时调整lambda和执行步数。运行B5/W5，与已有B10/W10形成两组比较：

```text
B10 对 W10：相同调用次数，比较质量/连续性
B5  对 W5 ：低计算预算下比较质量/连续性
B10 对 W5 ：比较能否以更低成本达到接近的质量
```

先用相同5任务与场景协议筛选；5次有潜力后才测试3次。减少NFE不改变32/16和环境执行频率。

GPU计时需要预热与正确同步，分开测视觉编码、动作积分、总重规划，报告平均与p95。另测无计时同步干扰的运行吞吐，不能把诊断同步开销当成部署固有成本。

**决策：**即使W10未提高成功率，只要W5较B5更好、并接近B10，就可沿效率方向推进。若平滑改善但质量退化超出预设范围，先进入P3或P4诊断，不直接宣传少步优势。

### 14.5 P3：缓存旧计划，进行4轮匹配训练

先固定baseline生成离线先验缓存，具体数据来源见第1.4和6.1节：第84帧观测预测84～115步，取100～115步作为第100帧样本的P。输入是更早观测，不能直接复制当前专家动作。

实施顺序：

1. 小批量生成缓存，检查episode、帧号、归一化与mask；
2. 验证DataLoader在shuffle后仍能按当前样本找到正确P；
3. 将训练起点改为Z、速度目标改为A-Z，未来特征辅助监督保持不变；
4. 先做一个batch前向/反向/保存/重载检查；
5. 再运行下述两组4轮微调。

| 训练组 | 起点分布 | 初始化与预算 |
|---|---|---|
| C-FT4 | 纯噪声 | 同一baseline epoch40，继续4轮 |
| R-FT4 | 50%纯噪声、50%尾部先验 | 同一baseline epoch40，继续4轮 |

两组LR、batch、scheduler、epoch、训练seed和原loss权重一致；先验组固定P1选定的sigma。混合比例0.5只是初始配方，暂不扩大扫描。

测试矩阵：

| 模型 | cold推理 | tail-prior推理 |
|---|---|---|
| C-FT4 | 必测 | P1启发式有潜力时增加 |
| R-FT4 | 必测 | 必测 |

先测试10NFE，再验证5NFE。R-FT4的cold表现用于检查首次启动与异常回退能力。缓存baseline与部署策略不同，匹配训练并不自动消除闭环偏差。

**决策：**在质量、效率或连续性上出现明确可复现收益后，再考虑完整scratch对照。正式scratch使用相同epoch规划、scheduler和预先确定的比较epoch；不把多训练4轮的收益全部归给先验。

### 14.6 P4：按现象选择一个分支

| 主要现象 | 优先实验 | 关键对照 |
|---|---|---|
| 平滑了，但失误后继续执行错误计划 | 观测驱动cold回退 | 始终复用、周期回退、同触发率随机回退 |
| 固定复用有效，但近远端需求不同 | 分段先验权重/噪声强度 | 全局固定sigma、分段sigma；匹配训练 |
| source复用不稳定，但旧尾部有信息 | 旧计划作为条件token | 原模型、条件token模型；不用source复用 |
| 只有低NFE明显获益 | 效率路线 | 完整成功率—延迟—连续性曲线 |
| 匹配训练后各项仍无改善 | 暂停此分支 | 记录负结果，回查实际瓶颈 |

不要在一次实验中同时加观测gate、计划token、逐位置时间。先用可解释规则验证，不能看到gate数值变化就认为有效。

### 14.7 P5：逐位置时间与流式生成

这是一条可选升级，不强制先完成复杂回退模块。

**P5a：逐位置时间训练。**模型接收每个动作位置的生成进度，改造时间条件、训练路径与采样更新。先完成全位置同时间时的退化一致性测试，再验证不同位置时间。

**P5b：同步滑动缓冲。**在受控步进中输出近端已完成动作、移动缓冲、补入新噪声，保留其他位置的生成状态。记录同一动作位置在移动前后的绝对时间映射，检查无重复/漏执行。

**P5c：异步执行。**最后引入实际/模拟推理延迟、执行中已承诺的动作前缀和并行推理。记录缓冲不足、等待、丢弃计划次数及控制频率。加入无复用、普通chunk同步执行、相应实时执行方法对照；不要把同步仿真计算时间直接解释为异步成功率。

每一步单独验收，不把三步合成一个难以排错的大改动。若目标是连续输出而非减少NFE，要报告环境动作输出频率和端到端运行时间。

### 14.8 正式验证、记录与结束标准

筛选出候选后，RoboTwin扩展到YF10全部任务、每任务50次、clean/randomized分别报告，逐步增加评测seed。Meta-World则使用自己固定的任务集合与协议，不与RoboTwin成功率做绝对比较。

同checkpoint推理消融使用配对初始场景和独立策略seed；训练方法的最终结论尽量增加至少3个训练seed。配对结果与按任务/seed分组的不确定性分析比只报一个总体百分比更重要。

每个实验目录建议保存：

```text
protocol.json       # 平台、任务、seed、H/E、NFE、主指标和质量容忍范围
config.yaml         # 实际生效配置快照
checkpoint_id.txt   # checkpoint路径/哈希、代码版本
episode_results.*   # 每次成功、步数、耗时、失败类型
generation_stats.*  # 视觉/DiT/总延迟、边界与内部变化
summary.*           # 分任务、分场景、分seed结果及比较
```

这些是拟议产物，不是已存在的新脚本接口。不要覆盖历史评测目录，也不需要为此重新划分用户全部训练数据；阈值和超参数应在固定的调试场景上确定，再用额外seed评测并如实记录选择过程。

结束标准按主目标判断：成功率接近但明显更快，可以保留为效率结果；质量接近但边界跳变稳定减少，可以保留为连续性结果。若匹配训练后所有指标仍无价值，就停止堆叠模块，优先回查视觉定位、动作表达、执行频率等真正瓶颈。

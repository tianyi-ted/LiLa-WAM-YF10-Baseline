# ABPolicy 设计融入 RoboTwin 两阶段 VLA 的技术路线

> 研究备忘：本文基于迁移前的 RoboTwin 两阶段模型，未同步改写为
> 当前 LiLa-WAM 单臂训练接口。请勿将其中的路径直接用于当前实验。

> 记录日期：2026-08-18  
> 状态：方案已确认，尚未开始模型结构改造  
> 目标平台：RoboTwin 仿真 + EDULITE A3 真实机械臂  
> 参考实现：`robot/ABPolicy-code`

## 1. 总体结论

保留当前两阶段 VLA 的语言理解、14 维 action、16 维 state 和真实机械臂安全控制框架，分阶段吸收 ABPolicy 中以下设计：

1. 统一训练与推理的图像分辨率、宽高比和预处理；
2. 使用三次 B 样条改善 L1～L6 的动作块内部及块间连续性；
3. 使用异步推理时间戳和已执行动作进行延迟感知的轨迹拼接；
4. 将单帧 state 扩展为多帧 state 历史条件，但不改变单帧维度定义；
5. 正式接通冻结的 DINOv2 稠密视觉特征；
6. 增加第二相机时，采用带相机身份编码的 token 级融合；
7. 验证上述模块后，再考虑把 Stage 1 的离散动作输出正式改为 B 样条控制点。

不直接照搬 ABPolicy 的整套工程。当前 ABPolicy 仓库存在推理依赖缺失、LoRA 配置未生效、DINOv2 预处理不完整、padding mask 未使用、异步线程退出不完整等问题。

## 2. 必须保持不变的接口

### 2.1 动作与状态语义

- 单帧 `action` 保持 14 维；
- 单帧 `state` 保持 16 维；
- 真实单臂继续放在模型兼容格式的左臂槽位；
- 右臂占位维度继续保持为 0；
- 不改变已有 HDF5 数据中各维度的物理含义；
- 不进行机械臂零位重新校验。

### 2.2 L7 夹爪

L7 不直接套用 L1～L6 的 B 样条连续轨迹控制，继续保留现有的：

- EMA 目标滤波；
- 最大目标变化率限制；
- 位置范围限制；
- 电流与力矩保护；
- 夹取停转/接触锁存；
- 释放动作解除锁存；
- 模型原始输出、过滤目标和实际反馈的独立记录。

原因是夹爪动作带有明显的开、合和接触事件。过强的 B 样条平滑可能推迟夹取时刻，并与力矩锁存逻辑冲突。

### 2.3 真实机械臂安全层

任何新模型输出都必须继续经过现有安全层，不允许模型直接发送到电机：

```text
模型输出
  → 反归一化
  → B样条/动作拼接（L1～L6）
  → 关节范围检查
  → 速度和单步变化限制
  → 关节滤波
  → L7专用滤波与力矩锁存
  → 反馈和通信超时检查
  → EDULITE A3 SDK
```

## 3. 目标模型结构

```text
语言指令 + RGB图像
        │
        ▼
   冻结 Qwen3-VL
   语义/任务特征
        │
        ├─────────────────────────┐
RGB图像 ─→ 冻结 DINOv2            │
           稠密空间特征            │
        ├─────────────────────────┤
最近4～8帧16维state → State Encoder│
                                  ▼
                         Stage 2 条件 DiT
                                  │
                         B样条控制点/动作块
                                  │
                     延迟感知的前缀重拟合
                                  │
                    L1～L6连续关节动作轨迹
                                  │
          L1～L6安全滤波 + L7独立安全控制
                                  │
                           EDULITE A3
```

Qwen3-VL 和 DINOv2 的职责不同：

- Qwen3-VL：语言指令、目标语义和任务阶段；
- DINOv2：局部纹理、目标边界、位置关系和稠密视觉对应；
- state 历史：运动方向、跟踪滞后和近期机械臂动态；
- Stage 1：动作先验；
- Stage 2：依据视觉、语言和状态修正动作分布。

DINOv2 不是深度模块。如果需要真实度量深度，应增加 RGB-D 相机及独立深度编码器。

## 4. 分阶段实施计划

## Phase 0：建立可信基线

### 目标

消除当前训练和真实推理之间的视觉输入分布差异。完成前不评价 DINOv2、第二相机或 B 样条的最终收益。

### 当前已知问题

- 正式采集 YAML 现在申请 `640×360`，相机实际输出也是 `640×360`；
- HDF5 保存实际图像，不主动缩放；
- 当前训练 DataLoader 隐式缩放到 `320×240`，改变了 16:9 宽高比；
- 当前真实推理直接使用 `640×360`；
- 因此训练和推理的图像尺寸、宽高比和视觉 token 数不一致。

### 修改要求

- 在 YAML 中显式声明统一的模型输入尺寸；
- 训练和推理共用同一个预处理函数；
- 优先使用保持 16:9 且适合视觉 patch 的尺寸，例如 `448×256`；
- 如果显存充足，可测试接近原始图像的 `640×352`；
- 禁止再依赖 DataLoader 的隐藏默认尺寸；
- 将模型实际收到的图像尺寸和视觉 token 数写入启动日志。

### 验收

- 同一张图像在训练与推理入口生成相同形状的 tensor；
- 宽高比不发生非等比例变形；
- 随机抽取训练样本，与真实推理预处理结果进行像素级对照；
- 建立当前模型的固定测试场景和成功率基线。

## Phase 1：现有 checkpoint 的推理后 B 样条拼接

### 目标

不重新训练模型，先验证 B 样条能否减少 L1～L6 动作块边界跳变。

### 方法

对每次模型生成的 32 帧动作：

```text
最近8帧已发送的L1～L6动作
        +
模型预测的未来32帧L1～L6动作
        ↓
构成40帧轨迹
        ↓
用8个控制点的三次B样条拟合
        ↓
根据推理延迟和已执行前缀重拟合前4个控制点
        ↓
重建40帧轨迹并丢弃已过期前缀
        ↓
执行未来动作
```

推荐初始参数：

```yaml
runtime:
  bspline_postprocess:
    enabled: false
    history_horizon: 8
    future_horizon: 32
    degree: 3
    num_control_points: 8
    free_prefix_control_points: 4
    last_free_point_weight: 0.05
```

必须通过配置开关启用，以便一条参数恢复原有推理。

### 实现注意事项

- 初始化历史不能填全0，应使用当前反馈或当前保持目标重复填充；
- 用单调时钟记录图像观测时刻、推理完成时刻和动作发送时刻；
- 优先使用已发送动作做命令连续性拼接，同时记录实际反馈用于分析跟踪误差；
- 对 `delay_steps` 设置上限；
- 必须保证重拟合后仍至少有足够的未来动作可执行；
- L7 从轨迹中分离，继续走现有夹爪安全控制；
- B 样条输出后仍需经过关节限位与速度限制。

### 验收指标

- chunk 边界最大关节目标跳变量；
- 一阶速度和二阶加速度峰值；
- 模型原始目标、B 样条目标、最终发送目标和反馈的误差；
- 单轮推理延迟及对应的 `delay_steps`；
- 任务成功率不能明显低于无 B 样条基线。

## Phase 2：多帧 state 条件

### 目标

让模型理解机械臂近期的运动方向和真实系统滞后。

### 数据接口

单帧定义保持不变：

```text
state[t] = 16维
```

训练样本改为：

```text
state_history = [state[t-H+1], ..., state[t]]
形状：[B,H,16]
```

初始建议：

```yaml
dataset:
  state_history_horizon: 4
```

验证有效后再测试8帧。

### 模型修改

```text
[B,H,16]
  → 16→256→512 State MLP
  → 加入时间位置编码
  → [B,H,512]
  → 作为独立 cross-attention 条件
```

### 验收

- state 历史索引和相机时间戳严格对应；
- episode 开头padding mask正确参与注意力或损失；
- 对快速移动、停止和改变方向场景单独评估；
- 对比单帧、4帧和8帧设置。

## Phase 3：正式接通冻结 DINOv2

### 当前状态

现有两阶段模型虽然保留 `use_vision_encoder_feat` 和 DINO adapter 接口，但 Stage 2 构建和 wrapper 没有完整接通，训练与真实推理实际传入的是：

```python
dino_features = None
```

因此当前 checkpoint 没有使用 DINOv2。

### 修改方案

新增明确配置：

```yaml
model:
  rgb_dense_encoder:
    enabled: false
    type: dinov2
    checkpoint_path: facebook/dinov2-base
    frozen: true
    input_size: [448, 256]
    feature_dim: 768
    adapter_dim: 512
    num_queries: 32
```

数据链路：

```text
同一张预处理一致的RGB
  → DINOv2标准processor/mean-std归一化
  → 去除或保留CLS后取得patch tokens
  → DINO adapter：768→512并压缩token
  → 与Qwen条件token沿token维拼接
  → Stage 2各层cross-attention
```

### 训练策略

- 第一版冻结DINOv2；
- 只训练DINO adapter、Stage 2和必要的条件融合层；
- 不直接照搬 ABPolicy 中未实际生效的 LoRA 配置；
- 小数据集下不优先全量微调DINOv2；
- 新条件分支可使用低初值门控，避免训练初期破坏原VLA条件。

### 验收

- 启动日志确认DINO不是 `None`；
- 记录DINO输入、patch token和adapter输出形状；
- 通过遮挡、方块位置变化和背景变化测试泛化；
- 对比同数据、同训练轮次的Qwen-only与Qwen+DINO。

## Phase 4：第二相机与多视角融合

### 相机建议

- 保留当前固定主相机；
- 第二相机放置在与主相机有明显基线的侧上方；
- 优先减少夹爪遮挡和前后深度歧义；
- 两相机固定曝光、白平衡、帧率和分辨率；
- 保存硬件或软件同步时间戳。

### 数据结构

继续按相机名分组：

```text
observation/head_camera/rgb
observation/side_camera/rgb
```

相机顺序必须在训练和推理中固定，并写入 HDF5 元数据和模型配置。

### 融合方式

不采用 ABPolicy 中将两台相机对应位置patch沿通道直接拼接的方式。采用：

```text
head tokens + learned head_camera embedding
side tokens + learned side_camera embedding
                    ↓
             沿token维拼接
                    ↓
              条件adapter/attention
```

这样不要求两个视角的patch在像素空间一一对应。

### 验收

- 单主相机与双相机使用相同训练轮数和测试初始位置；
- 分别统计无遮挡、部分遮挡和明显深度变化场景；
- 记录去掉任一相机后的性能变化，检查模型是否真正利用第二视角。

## Phase 5：训练原生 B 样条动作头

只有 Phase 1 验证 B 样条不会损害任务意图后，才进入本阶段。

### 训练目标

把过去8帧和未来32帧动作组成40帧轨迹：

```text
[B,40,14]
   → 三次B样条拟合
[B,8,14]
```

Stage 1 和 Stage 2 预测8个控制点，而不是32个离散未来动作。推理后再重建40帧，并根据实际延迟重拟合前缀。

### 兼容性

- 该改动会改变模型输出结构；
- 现有 Stage 1/Stage 2 checkpoint 不能直接作为完整新模型加载；
- 可以尝试复用视觉语言模型和部分条件adapter，但动作头需要重新训练；
- 训练数据中的14维action语义保持不变；
- 右臂7维零占位继续参与拟合，理论上仍保持接近0。

### 需要额外验证

- 原始动作到B样条重建动作的每关节MAE和最大误差；
- 抓取、闭爪和释放关键时刻是否被平滑偏移；
- 对L7单独计算重建误差，并决定训练目标中是否对其禁用B样条；
- B样条输出模型与离散动作输出模型的任务成功率对比。

## 5. 深度相机的独立路线

DINOv2只编码RGB，不提供新的物理深度观测。深度相机应作为独立实验，不与DINOv2混为一项改动。

推荐顺序：

1. 先将深度用于诊断、三维目标定位和抓取误差分析；
2. 验证深度质量、RGB对齐和相机外参；
3. 再增加深度编码分支；
4. 最后考虑通过视觉伺服或IK对模型目标做小范围修正。

建议HDF5结构：

```text
observation/<camera>/rgb       uint8/JPEG
observation/<camera>/depth     uint16，单位毫米
observation/<camera>/valid     可选有效掩码
```

深度模型输入建议为：

```text
[归一化米制深度, 有效像素mask]
```

经轻量Depth Patch Encoder与adapter变成条件token。不要把原始深度图直接当作自然RGB输入冻结的DINOv2。

## 6. 统一实验矩阵

所有方案使用相同的数据划分、训练轮数、目标初始位置和机械臂安全参数。

| 实验 | 图像 | DINOv2 | state历史 | B样条 | 用途 |
|---|---|---|---|---|---|
| A | 单RGB，预处理统一 | 否 | 1帧 | 否 | 新基线 |
| B | 单RGB | 否 | 1帧 | 仅推理后处理 | 验证轨迹连续性 |
| C | 单RGB | 否 | 4/8帧 | 推理后处理 | 验证动态信息 |
| D | 单RGB | 是 | 4/8帧 | 推理后处理 | 验证稠密视觉特征 |
| E | 双RGB | 是 | 4/8帧 | 推理后处理 | 验证遮挡和深度线索 |
| F | 最优视觉配置 | 是 | 最优设置 | 原生B样条动作头 | 最终结构 |

每次只增加一个主要变量，避免无法判断提升来源。

## 7. 统一记录指标

### 7.1 模型与视觉

- 输入图像实际尺寸和宽高比；
- 每个相机的输入时间戳；
- Qwen视觉token数；
- DINO patch token数；
- 单次模型推理时间；
- action chunk生成时间戳及对应观测时间戳。

### 7.2 动作与机械臂

- 模型原始14维动作；
- B样条重建动作；
- 安全层过滤后的发送动作；
- 实际关节反馈；
- 每关节位置跟踪误差；
- chunk边界跳变量；
- 速度、加速度峰值；
- L7原始目标、过滤目标、角度、力矩、电流和锁存状态。

### 7.3 任务表现

- 是否成功接近方块；
- 是否成功闭爪；
- 是否成功抓起；
- 是否成功移动至盒子；
- 是否成功释放；
- 最终整轮成功率；
- 失败类型：定位偏差、深度偏差、遮挡、夹爪时序、轨迹不连续或机械跟踪问题。

## 9. 实施原则与回退方案

- 所有新功能默认关闭，先保持旧流程可运行；
- 每项改动提供独立 YAML 开关；
- 训练和推理必须从同一配置读取视觉预处理；
- checkpoint必须保存完整配置、统计量和输入模式；
- 加载checkpoint时校验图像尺寸、相机顺序、state历史长度和动作表示；
- 新旧动作表示使用不同checkpoint目录，避免误加载；
- 每阶段完成仿真离线测试后，再进入真实机械臂低速测试；
- 真实测试始终保持物理急停可触及；
- 若任务成功率或安全指标退化，可用单个配置开关恢复上一阶段。

## 10. 下一步执行顺序

- [ ] Phase 0：显式统一训练和推理图像预处理；
- [ ] 保存统一视觉基线checkpoint并完成固定场景测试；
- [ ] Phase 1：只对L1～L6加入可关闭的B样条推理后处理；
- [ ] 对比原始与B样条轨迹日志；
- [ ] Phase 2：增加4帧state历史并重训；
- [ ] Phase 3：接通冻结DINOv2并重训Stage 2；
- [ ] Phase 4：增加第二相机和token级多视角融合；
- [ ] 根据实验结果决定是否增加真实深度分支；
- [ ] Phase 5：训练原生B样条动作头；
- [ ] 将最佳结构同时验证在RoboTwin与EDULITE A3上。

---

本路线的核心原则是：先消除数据链路不一致，再处理动作连续性，然后增加状态历史和稠密视觉，最后才改变训练目标。这样每一步都有明确对照、可独立回退，也更容易判断抓取精度改善究竟来自哪里。
